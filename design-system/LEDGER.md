# PIZZY LEE'S BUILD PACK — SKILL 9: THE VARIETY LEDGER

The memory of every independent design system this pack has shipped, plus the full reference vocabulary it can rotate against. The variety protocol in 01-ui-ux-design.md reads this file before assembling a new system and appends to it after approval. It does not force novelty into an existing product, a refinement, or another page in the same product. One entry per approved system. Newest first.

This file has three uses:
- **Pack reference (read-only):** this file, `09-ledger.md`, is reference material and rotation rules. Builds must never append to it or edit its entries.
- **Project copy (writable):** copy this file into any new project's `design-system/` folder as `LEDGER.md`. That copy belongs inside each project repo, next to its design document and `pages/`, never in the pack folder or workspace root. Project entries are appended only to the project copy, only after Lee approves the design and asks for the record.
- **Reference:** attach this file with its usage prompt (`prompts/09-ledger.prompt.md`) when the thinking AI needs the variety memory in a fresh chat.

Everything in the Reference Vocabulary below is compiled from the pack's researched sources (01-ui-ux-design.md catalogs, hallmark-derived structure rules, Magic UI catalog, taste-skill palette alternatives, brand worlds). Source tagged per section. Nothing invented.

## Rotation rules (what the next project must NOT do)

These rules apply only when Lee approves a new independent design system and the brief leaves the relevant axis open. User direction, supplied references, accessibility, platform conventions, and existing product evidence override rotation. Do not change theme, navigation, component language, or typography in an existing product just to satisfy this ledger.

1. Use the same style catalog entry as any of the last 3 projects.
2. Use the same font pairing as the last 2 projects.
3. Use the same palette family as the last 2 projects.
4. Ship the same theme mode (light / dark / both) twice in a row unless the product demands it.
5. Share more than 3 of the 6 structural fingerprint axes with the previous project.
6. Reuse the same nav archetype or footer archetype as the previous project.
7. If a signature component is justified, do not use the same signature family as the last 2 independent projects. `None` is valid and does not count as a repeated family.
8. Match the previous project on both VARIANCE and MOTION dials at once.
9. Use the same landing pattern as the previous project when the product type is the same.
10. Land in the same design quadrant twice in a row. A minimal+light project is followed by something in a different quadrant.

## Field guide (fill every line for every entry)

- Product type: the catalog entry used from the product design systems in 01-ui-ux-design.md.
- Style: style name + ID from the style catalog in this file.
- Palette: the core colors plus the accent, and the family name from the palette families list.
- Fonts: the pairing name from the font pairings list.
- Theme: light / dark / both.
- Dials: VARIANCE / MOTION / DENSITY (1-10) plus ENERGY / RHYTHM / MOTION (1-3).
- Fingerprint: one choice per axis from the six-axes list.
- Landing pattern: name from the landing patterns list for Persuade surfaces; `N/A, task-led` for Operate or Read surfaces.
- Nav / footer: archetype names from the nav and footer archetype lists.
- Motion tier: subtle / standard / complex.
- Background & depth: the designed surface treatment and elevation language.
- Signature: a justified memorable element named from the signature families list, or `None`.
- Design read: the one-line read declared before generation.
- Notes: what made this design specific to this brief, not to the product category.

### D. Structural fingerprint axes (source: hallmark, distilled in 01-ui-ux-design.md)

One choice per axis per project. Rotation rules 5: no more than 3 shared axes with the previous project.

1. **Heading placement** — hanging (floats in space above) / centered display / bottom-aligned / overlapping image / sticky or pinned / inline with body. (Left-margin and numbered "01." headings exist but are opt-in only: the most recognized AI tells.)
2. **Body composition** — single column / two-column asymmetric / multi-column justified / marginalia / three-column equal / full-bleed with margin reset / asymmetric spans.
3. **Divider language** — hairline rule / ornament / negative space alone / bleed-color block / double rule.
4. **Button voice** — outlined / unstyled link / oversized solid / typographic-only / form-as-CTA.
5. **Image treatment** — full-bleed / tightly cropped / inline with text / margin-aligned / none.
6. **Reveal pattern** — fade-up stagger / horizontal sweep / type-unmask / number-tick / typewriter / none.

### E. Nav and footer archetypes (source: hallmark component archetypes)

Nav: N1a minimal 2-link / N1b canonical three-section / N2 floating chip / N3 side-rail / N4 hidden Cmd-K / N5 floating pill / N6 masthead / N7 brutal slab / N8 terminal / N9 edge-aligned / N10 scroll-morph / N11 mega-menu / N12 banner + retract / N13 inline Cmd-K pill.

Footer: Ft1 mast-headed / Ft2 inline single line / Ft3 index columns / Ft4 dense colophon / Ft5 statement / Ft6 letter close / Ft8 marquee scroll. (Ft7 is not named in the source.)

Default-away guidance from the same source: N1a and Ft3 are the most recognized AI thumbprints; use them only when the page genuinely fits. N4 and N13 Cmd-K chrome also appear in Lee's rejected cluster; use them only when the brief demands keyboard-first navigation.

### H. Dials (sources: 01-ui-ux-design.md protocol, 08-anti-slop-filter.md liveliness toolkit)

- VARIANCE 1-10: 1-3 predictable and symmetric / 4-7 offset and balanced / 8-10 asymmetric and bold.
- MOTION 1-10: 1-3 static with hover states / 4-7 standard scroll and stagger / 8-10 cinematic choreography.
- DENSITY 1-10: 1-3 art gallery / 4-7 standard app / 8-10 cockpit.
- ENERGY 1-3: how hard the design says hello (1 Linear, GOV.UK / 2 Stripe, Vercel / 3 Awwwards).
- RHYTHM 1-3: how much sections change from each other (1 uniform / 2 few breaks / 3 asymmetric mix).
- MOTION 1-3: how much motion, and why (1 hover only / 2 scroll reveal / 3 pin and choreography).

### I. Motion tiers (sources: 01, 02)

Subtle / Standard / Complex. Maps to the MOTION dial and to the GSAP and Magic UI presets.

### J. Theme modes

Light / Dark / Both. Chosen from brand and users (antislop R-21); no "dark because tech" defaults. Both modes must work when a toggle ships.
